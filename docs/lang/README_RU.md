# dsh-effort-slider

> **Слайдер уровня рассуждений в стиле Claude Code для DeepSeek Harness** — нажмите **Effort** в меню моделей, тяните без ступеней, при отпускании значение прилипает к уровню, огненный след на WebGL; любая сторонняя модель / любой провайдер получает реально работающее управление усилием рассуждений.

## Возможности

| Возможность | Описание |
| --- | --- |
| 🎚️ Бесступенчатое перетаскивание | Непрерывное перетаскивание 0–100 с записью `reasoningEffort` в реальном времени (троттлинг 16 мс, без накопления запросов при перетаскивании) |
| 🎯 Прилипание при отпускании | При отпускании / потере фокуса / завершении клавиатурного ввода прилипает к ближайшему уровню и отправляет одну подтверждающую запись |
| 🔥 Огненный след WebGL | Трёхпроходные шейдеры (воспламенение → размытие → композиция); фронт огня следует за бегунком с пружинным демпфированием |
| 🏁 Метки OFF/MAX | Первый и последний уровни всегда показывают `OFF` / `MAX`; промежуточные уровни показывают имя, возвращённое API |
| 🎨 Статус уровня | Имя усилия показывается в шапке панели, раскрашивается/светится по уровню; строка меню и триггер модельного места сохраняют тот же цвет после закрытия (v0.2.3) |
| 🌐 Универсальные усилия | Сторонние модели без метаданных `reasoning` автоматически получают универсальную шкалу из 5 уровней; моделям pi-ai дописываются словари на уровне сети, **применяется на лету** (v0.2.0) |

Записывается только `reasoningEffort` — выбор модели не затрагивается. Модели без многоуровневого рассуждения показывают 「当前模型不提供多档推理等级」 (текущая модель не предоставляет несколько уровней рассуждений).

### Универсальное предоставление усилий (v0.2.0, упрощено в v0.3.0)

**Любая сторонняя модель/провайдер получает управление усилием рассуждений, которое реально действует на уровне сети**:

- **Предоставление на уровне сети (хост, pi-ai)**: для моделей `llm-pi-ai` без `reasoningEfforts` дописываются словарь и сетевой диалект `compat` (**на лету, без перезапуска**); pi-ai переводит уровень в реальные поля сети (`reasoning_effort` / `thinking` / OpenRouter `reasoning.effort` и т.д.) **и** публикует то же объявление как метаданные `reasoning` каталога модели — именно поэтому у вручную объявленной модели вообще появляется официальная строка **Effort**;
- **Резервная шкала на клиенте**: если каталог не возвращает метаданные рассуждений, панель всё равно открывается с универсальной шкалой из 5 уровней;
- Существующие объявления пользователя (`reasoningEfforts: false` или свой словарь) всегда уважаются и никогда не перезаписываются.

> **Почему больше нет обёртки адаптеров.** До v0.2.5 хост-часть также оборачивала `resolveModel` каждого адаптера, чтобы внедрять `universalReasoning` в модели без метаданных `reasoning`. В DSH 0.1.5 `llm.adapters` стал приватным полем без публичного акцессора — этот путь стал невозможным, и больше не нужен: `reasoningEfforts` — единственное объявление, которое питает и запрос по сети, и каталог моделей. `compat` на уровне модели записывается только когда маршрут объявляет `api: openai-completions`, потому что pi-ai отвергает переключатель, который протокол модели не может прочитать.

Поддерживаемые сетевые диалекты для сторонних эндпоинтов (задайте `effort-slider.defaultDialect` или `routes.<маршрут>`).
Диалект переводит уровни только на маршрутах `api: openai-completions` — нативные протоколы используют встроенное
сопоставление pi-ai, так что настройка диалекта там на провод не влияет:

| Диалект | Эффект в сети |
| --- | --- |
| `effort` (по умолчанию) | `reasoning_effort: low/medium/high/max` в стиле OpenAI |
| `deepseek` | переключатель `thinking:{type}` + `reasoning_effort` |
| `openrouter` | `reasoning: { effort }` (нормализация OpenRouter) |
| `together` / `zai` | `reasoning.enabled` / `thinking:{type}` + необязательный effort |
| `qwen` | переключатель `enable_thinking` |
| `string-thinking` / `ant-ling` | строки `thinking` / `reasoning.effort` |

## Установка / Удаление

```sh
# Установка из npm (пакет, добавленный в каталог deepseek1024.com)
dsh plugin --profile web add @txc2768651338/dsh-effort-slider

# Или установка с GitHub (собранные артефакты lib/ закоммичены, локальная сборка не нужна)
dsh plugin --profile web add github:2768651338/dsh-effort-slider#main

# Или собрать локально и установить из checkout
pnpm install && pnpm build
dsh plugin --profile web add file:./dsh-effort-slider
```

> После установки **перезапустите DeepSeek Harness** и один раз нажмите **Ctrl+F5** на веб-странице.
> Артефакты `lib/` закоммичены, поэтому установка с GitHub не требует локальной сборки.

**Приходите с версии, закреплённой за старым DSH?** Удалите строку `- id: ui-effort-slider` / `disabled: true` из `~/.dsh/profiles/web/cordis.patch.yml`, иначе новая сборка останется выключенной.

| Действие | Команда |
| --- | --- |
| Обновление | `dsh plugin --profile web update @txc2768651338/dsh-effort-slider` (или повторный `add`), затем перезапуск DSH |
| Удаление | `dsh plugin --profile web remove @txc2768651338/dsh-effort-slider`, и удалить его строку из `cordis.patch.yml`, если есть |

## Быстрый старт

1. Установите плагин, перезапустите DSH, нажмите `Ctrl+F5`.
2. Откройте меню моделей над полем ввода → нажмите **Effort** → появится панель со слайдером Effort.
3. Тяните, чтобы выбрать уровень; при отпускании значение прилипает. После закрытия панели значение уровня сохраняет свой цвет на строке меню.
4. Для сторонних моделей без усилия рассуждений панель открывается с универсальной шкалой из 5 уровней; моделям pi-ai словари сети дописываются на хосте (на лету).

Строка `[effort-slider] intercept row: ...` в консоли DevTools означает, что перехват работает.

## Конфигурация

| Пункт | Подробности |
| --- | --- |
| Опции плагина | конфигурация profile entry плагина (`enabled` / `defaultDialect` / `routes` / `debugReport`), редактируется на странице настроек DSH (автоматически сгенерированная форма), применяется при перемонтировании плагина |
| Значения по умолчанию | `enabled: true`, `defaultDialect: effort`, `debugReport: false` |
| Переменные окружения | своих нет; следует разрешению `DSH_HOME` в DSH |
| Чувствительные данные | нет — ключи, токены и учётные данные не читаются и не сохраняются |

```yaml
effort-slider:
  enabled: true          # главный выключатель предоставления
  defaultDialect: effort # сетевой диалект по умолчанию
  routes:
    my-gateway: deepseek # переопределение по маршруту
  debugReport: false     # отчёт о предоставлении за каждый запуск (маршрут/модель/диалект/записано-или-пропущено) + трассировка усилия по каждому запросу (llm/stream) в лог хоста
```

## Права и данные

| Область | Что затрагивает |
| --- | --- |
| Файлы (чтение) | нет — пользовательские файлы не читаются и не пишутся (настройки идут через сервис settings DSH) |
| Сеть | своих запросов нет — панель читает и пишет общий каталог Model Controller в браузере; итоговый вызов `session.selectModel` идёт по существующему соединению DSH |
| Учётные данные | никогда не читаются |
| Данные пользователя | не читаются (нет доступа к содержимому переписки/сообщениям/промптам; только provider/model/`reasoningEffort` текущей сессии через общий каталог моделей) |

## Как это работает

| Половина | Файл | Роль |
| --- | --- | --- |
| Хост | `lib/index.js` | Универсальное предоставление усилий: находит profile entry pi-ai (`llm-pi-ai`), читает её через `settings.describe()`, дописывает сетевые диалекты через `settings.mutate` (`buildProvisionOps`, идемпотентно, уважает объявления пользователя); слушает `llm/adapters-updated` / `settings/document-updated`. С `debugReport: true` каждый запуск выводит отчёт по маршруту/модели (записанные поля или причина пропуска, с пометкой, где диалект не применяется) вместо однострочного счётчика, а каждый вызов модели трассируется как `[debug] request route=… model=… effort=…` через read-only прохождение `llm/stream` |
| Браузер | `lib/client.js` | Перехватывает клики по строке Effort меню моделей → показывает панель Effort; читает `ctx.modelDirectories.directoryFor(sessionId)` и пишет через `directory.select({ reasoningEffort })`; MutationObserver поддерживает цвет уровня на строке меню после закрытия панели |

> Браузерная часть следует официальной конвенции внешних плагинов: классический скрипт + фабрика `window.__ModuleLoader__.load`; `react` / `react-dom/client` / `react/jsx-runtime` — платформенные externals; `effort.module.css` хешируется и встраивается lightningcss, инъекция как `<style data-plugin>` при запуске фабрики.

## Устранение неполадок

| Симптом | Решение |
| --- | --- |
| В меню моделей нет строки Effort | Модель не объявляет метаданные рассуждений, и предоставление на хосте не действует — убедитесь, что DSH перезапускался, и проверьте `enabled` на странице настроек плагина (его конфигурация profile entry); задайте `debugReport: true` и проверьте лог хоста на предмет отчёта о предоставлении по каждой модели |
| Панель пишет 「当前模型不支持思考强度调节」 | Универсальный резерв не активен — обновитесь до v0.2.0+ и перезапустите |
| Плагин вообще не загружается (строка помечена `disabled: true`) | Ранняя сборка была выключена в `~/.dsh/profiles/web/cordis.patch.yml`; удалите эту строку и перезапустите |
| Перетаскивание не действует | Проверьте, совпадает ли сетевой диалект целевого эндпоинта (см. таблицу диалектов — диалекты переводят только на маршрутах `api: openai-completions`), или задайте `defaultDialect` для этого маршрута. С `debugReport: true` лог хоста покрывает всю проверяемую цепочку: отчёт по модели точно говорит, что было записано (или пропущено, и почему), и помечает маршруты, где диалект не применяется, а строки `[debug] request route=… model=… effort=…` доказывают, какой уровень несёт каждый вызов. Остаётся только проводная трансляция внутри pi-ai, которую не может наблюдать ни один плагин. Кнопка `?` панели повторяет этот чек-лист |
| Конфликты с другими плагинами-скинами | Если установлен другой скин, перехватывающий строку Effort (например, скин aurora из dsh-ui-web), отключите его перехват, чтобы избежать двойных панелей |
| После перезапуска версия всё ещё старая | Установки `file:` — снапшот-копии; используйте спецификацию `github:` или повторите `add`, затем перезапустите |
| Где логи? | Ошибки хоста: лог запуска DSH (с `debugReport: true` детали предоставления и трассировки усилия по запросам выводятся строками `effort-slider: [debug]`); ошибки клиента: консоль DevTools браузера (F12) (префикс `[effort-slider]`) |

## Структура проекта

```text
src/
  index.ts                  хост-половина: сетевое предоставление pi-ai через шов SettingsForms
  effort-core.ts             чистая логика: сетевой диалект → маппинг, генерация патчей предоставления (юнит-тесты)
  client/
    index.ts                браузерная половина: перехват строки Effort + якорь панели + раскраска строки меню
    css-modules.d.ts
    effort/
      directory.ts          структурная грань ctx.modelDirectories / ctx.sessions (только типы, без импорта рантайма DSH)
      EffortPanel.tsx       Панель Effort (уровни / метки / слайдер / свечение)
      useWebglFire.ts       Трёхпроходный огненный цикл WebGL2 (пружинное следование + сон в простое)
      shaders.ts            вершинные / воспламенение / размытие / композиция шейдеры
      effortColors.ts       уровень → цвет (панель и строка меню делят его)
      effort.module.css     стили панели (встраиваются через lightningcss)
cordis.patch.yml           патч бандла (вставляет строку ui-effort-slider)
lib/                       собранные артефакты (client.js с sourcemap)
test/                      юнит-тесты host.spec.mjs + host-apply.spec.mjs + client.smoke.mjs
```

## Разработка

```sh
pnpm install
pnpm build       # tsdown → lib/index.js (хост-половина) + lib/client.js (браузерная половина)
pnpm typecheck   # tsc --noEmit (зелёный против @deepseek-ai/* 0.2.0-rc.2)
pnpm test        # юнит-тесты хоста + интеграция apply + интеграция реального шва + jsdom-дым
```

Слои `test/`, от самого дешёвого:

| Файл | Охват |
| --- | --- |
| `host.spec.mjs` | Чистая логика: сетевой диалект → маппинг, генерация патчей предоставления, идемпотентность |
| `host-apply.spec.mjs` | `apply()` на замоканном cordis-контексте: повтор при поздней регистрации entry pi-ai, гейтинг `compat` по объявленному протоколу, идемпотентность `settings/document-updated` |
| `host-integration.spec.mjs` | **Реальный шов**: настоящий `@deepseek-ai/cordis` + верный дубль шва `SettingsForms` (в npm-пакетах 0.2.0 нет отдельного провайдера) — обнаружение entry, реальные записи path-op, попадающие в конфигурацию profile entry, и записанные `reasoningEfforts`/`compat` проходят правила валидации pi-ai |
| `client.smoke.mjs` | jsdom: материализация фабрики бандла, перехват строки Effort, рендер панели, записи drag/snap через `directory.select`, раскраска, уборка при размонтировании |

**Вклад.** Fork → изменить → `pnpm build` → запустить `pnpm test` → открыть PR в `main`. Мелкие правки (документация, тесты) приветствуются без предварительного обсуждения; в issues указывайте версию DSH и точный текст ошибки.
